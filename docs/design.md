## Problem Statement

VS Code 的 rg（ripgrep）全局搜索偶尔卡死，长时间无响应。需要一个通用工具，给任意二进制文件加超时包装，超时后自动 kill 并返回错误码 137（SIGKILL）。

## What Makes This Cool

一行 `npx` 就能给任意二进制加超时，透明代理，零感知。备份 + 替换模式，可逆。

## Constraints

- macOS 标配环境（有 perl，无 GNU timeout）
- shell 脚本必须完全透传 stdin/stdout/stderr
- wrapper 对调用方（如 VS Code）完全透明
- 超时默认 5 秒，可配置

## Premises

1. VS Code 通过 spawn 直接调用 rg，不关心二进制是否被替换为脚本
2. macOS 无 GNU timeout，需用 perl alarm 或 shell 后台进程实现
3. shell 脚本的 stdout/stderr 透传对 rg 的二进制输出格式（--json）足够

## Approaches Considered

### Approach A: Pure Shell (background + kill)
- Effort: S | Risk: Low
- Pros: 零依赖 POSIX sh
- Cons: 竞态条件，信号处理复杂

### Approach B: Perl alarm (CHOSEN)
- Effort: S | Risk: Low
- Pros: 一行搞定，零竞态，macOS 标配 perl
- Cons: 依赖 perl（macOS 标配）

## Recommended Approach

Perl alarm wrapper。核心 wrapper 脚本：

```sh
#!/bin/sh
# Auto-generated by @lionad/bin-timeout-wrapper
# Wraps: {bin_path}_backup
# Timeout: {timeout}s (override with BIN_TIMEOUT env var)

TIMEOUT="${BIN_TIMEOUT:-{timeout}}"
exec perl -e '
  alarm $ENV{BIN_TIMEOUT} || $ARGV[0];
  exec @ARGV[1..$#ARGV];
' "$TIMEOUT" "{bin_path}_backup" "$@"
```

### CLI 接口

```bash
# 包装二进制（带超时）
npx @lionad/bin-timeout-wrapper -- /path/to/bin --timeout 5

# 还原原始二进制
npx @lionad/bin-timeout-wrapper --restore -- /path/to/bin

# 查看当前包装状态
npx @lionad/bin-timeout-wrapper --status -- /path/to/bin
```

### 行为

1. `-- /path/to/bin --timeout N`:
   - 检查 `/path/to/bin` 是否已是 wrapper（避免重复包装）
   - 将 `/path/to/bin` 重命名为 `/path/to/bin_backup`
   - 在 `/path/to/bin` 创建 shell 脚本，内容为 perl alarm wrapper
   - `chmod +x` 确保 wrapper 可执行
   - 设置 `BIN_TIMEOUT` env var 默认值为 N

2. `--restore -- /path/to/bin`:
   - 检查 `/path/to/bin_backup` 是否存在
   - 删除 `/path/to/bin`（wrapper 脚本）
   - 将 `/path/to/bin_backup` 重命名回 `/path/to/bin`

3. `--status -- /path/to/bin`:
   - 检查是否已被包装
   - 显示当前超时设置和 backup 文件位置

### Wrapper 脚本细节

- perl alarm 超时后发送 SIGALRM，perl 默认处理是 die，exit code 142
- 需要在 perl 中捕获 SIGALRM 并明确 `kill 9, $$` 以返回 137
- 或者用 `$SIG{ALRM} = sub { kill 9, $$ }` 确保 SIGKILL
- env var `BIN_TIMEOUT` 允许运行时动态调整超时

### 包结构

```
@lionad/bin-timeout-wrapper/
  package.json
  bin/
    cli.mjs        # npx 入口，Node.js CLI
  lib/
    wrap.js        # 包装逻辑
    restore.js     # 还原逻辑
    status.js      # 状态检查
    template.sh    # wrapper 模板
```

CLI 用 Node.js（因为 npx 就是 Node 生态），但生成的 wrapper 是纯 shell + perl。

## Open Questions

- 是否需要支持 Windows？（当前设计仅 macOS/Linux）
- 是否需要日志记录超时事件？

## Success Criteria

- `npx @lionad/bin-timeout-wrapper -- /path/to/rg --timeout 5` 后 VS Code 搜索正常
- rg 执行超过 5 秒自动被 kill，返回 137
- `--restore` 能完整还原原始二进制
- 重复执行 `--` 包装命令不会重复嵌套

## Distribution Plan

npm 包 `@lionad/bin-timeout-wrapper`，通过 `npx` 直接使用，无需全局安装。
